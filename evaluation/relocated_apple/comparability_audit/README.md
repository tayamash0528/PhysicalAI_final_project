# 再観察手順の追加として比較は成立

既存20試行の実ファイルを照合した。全10ペアで初期状態hash・seedが同じ、setupの差はactive_reobservationだけ。実行された6ソースは事前LOCK・現在の採用コードと一致。重み、指示、画像キー・前処理・state/action仕様、相対制御、物理、v2収容判定、20Hz・総900step上限を共有する。証拠はexisting20_actual_pairs.json、親LOCK、manifest、execution_status、各result.json。

したがって、既存葉5条件の収容2/5→4/5は「評価した条件で、再観察手順を追加した場合に収容成功数が増えた」という確認済みの成果として扱う。把持保持は4/5→4/5であり別指標。

意図した差は次のとおり。

- 両方式とも初期RGBで同じ判断を計算するが、あり側だけ必要時に観察専用OSC移動を行う。なし側も画像を固定せず通常画像更新を使う。
- 観察は開口したまま45stepの小移動。実際の手首視点・アーム姿勢・VLA開始画像とstateが変わる。固定カメラは同じagentviewのまま。
- あり側は観察後にaction queueをresetし、新しい実画像とstateからVLA行動を生成する。移動中の主操作への置換はない。
- 観察2.25sim秒を共通45秒に含めるため、観察した場合の残りVLA上限は855step、なしは900step。操作開始時刻・接近経路・その後の画像と行動が変わる。
- 各episode開始時のPython/NumPy/Torch/CUDA seedを合わせ、policy/preprocessorをresetする。観察で変更された状態による後続行動の差は手順の効果に含む。

評価用の物体位置・個数は方策やRGB判断へ渡さない。準備は位置を使って初期シーンを作るが、実行setupはprepared stateファイル等だけで、方策入力は実RGB2視点・8Dロボットstate・同一指示。45stepの評価snapshotは保存専用。

この比較は視覚情報だけを独立に変えた実験ではない。情報・姿勢・接近経路・タイミングを含む手順追加の比較で、意図しないモデル・物理・判定差は見つからなかった。新規20についても同じ設定をPREFLIGHT.jsonで照合し、結果後は同一の解析で実行版と初期状態を再検査する。
