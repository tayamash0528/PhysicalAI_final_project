## キャッシュ・実行条件と限界

Docker buildでは主要install層がCACHEDだった。モデルとLIBEROアセットも既存キャッシュを読み取り専用で再利用し、ネットワークから全体を再取得していない。専用コンテナはdetached起動し、対話終了に依存しない方法で実行した後、終了コードを確認した。

requirements.lockは実測依存一覧でありDocker構築へ直接適用されていない。新規PC・空キャッシュで同一依存を再解決できた検証ではない。上流cloneのネットワーク取得、新規モデル・アセットの全量download、公開URL経由の配布ZIP取得も今回未実行。準備スクリプトのローカル取得・SHA検証と既存キャッシュ経路の実行結果と区別する。

初回のホスト準備ではWindowsの保護された一時領域の削除が拒否された。公開準備スクリプトの一時領域をプロジェクト内cacheへ変更し、作業内の領域であることを検査する方式で解消した。採用モデルや制御の不具合ではなく、以後の配布配置は成功した。
